Build & Verify

先把工程编过，并确认基础环境没问题

这一步只解决“工程是否能构建、基础工具链是否齐全”。后续模块示例默认基础构建环境已就绪。

环境要求

  • CMake 3.22+
  • Ninja
  • GNU Arm Embedded Toolchain
  • arm-none-eabi-gcc 等工具已进入 PATH

构建命令

cmake --preset Debug
cmake --build --preset Debug

产物默认在 build/Debug/，核心输出是 iFly_Ctrl.elf。

当前推荐验证方式

完成固件烧录后，可优先通过 USB CDC 连接 CLI，并执行下列命令确认调试环境可用。

help
params
call status
get sys.transport
call pid.sample 100 92 1

为什么只做这个验证

因为当前仓库已经稳定接好的仍是模块和调试基础设施，不是完整飞控应用层。先把 CLI、参数和 PID 验证通，比去假设闭环业务已经存在更可靠。

Usage Example

app_main：模块装配示例

app_main.cpp 给出了当前模块组合为最小应用入口的参考装配方式。

怎么用

用于当前工程的上层装配：初始化 IO、初始化 CLI、绑定 transport，并进入主循环轮询。

最小示例

#include "flight_ctrl_cli.hpp"
#include "hardware_uart.hpp"
#include "tick.hpp"
#include "usb_uart.hpp"

namespace {
constexpr uint32_t kCliRxQueueSize = 1024U;

iFly::HardwareUart g_uart5(iFly::UartPortId::kUart5, kCliRxQueueSize);
iFly::UsbUart g_usb(kCliRxQueueSize);
iFly::FlightCtrlCli g_cli;
}

extern "C" void app_main(void) {
  g_uart5.Init();
  g_usb.Init();
  g_cli.Init();
  g_cli.RegisterTransport("uart5", &g_uart5);
  g_cli.RegisterTransport("usb", &g_usb);
  g_cli.UseTransport("usb");

  while (1) {
    g_cli.Poll();
    iFly::tick::DelayMs(1U);
  }
}

Usage Example

FlightCtrlCli：怎么用

用于快速构建支持登录、调参与通信通道切换的控制台。

典型用法

  • 先构造底层 transport 对象。
  • 再构造 FlightCtrlCli。
  • 调用 Init()。
  • 注册 transport 并选择当前通道。
  • 在主循环持续调用 Poll()。

最小示例

iFly::HardwareUart uart5(iFly::UartPortId::kUart5, 1024U);
iFly::UsbUart usb(1024U);
iFly::FlightCtrlCli cli;

uart5.Init();
usb.Init();

cli.Init();
cli.RegisterTransport("uart5", &uart5);
cli.RegisterTransport("usb", &usb);
cli.UseTransport("usb");

for (;;) {
  cli.Poll();
}

Usage Example

ParameterManager：怎么用

用于将运行时变量暴露给 Shell，并通过 get / set 统一管理。

典型用法

  • 先准备一个 Shell 对象。
  • 再构造 ParameterManager。
  • 按类型添加参数描述。
  • 最后调用 RegisterToShell()。

最小示例

float kp = 0.8f;
uint32_t loop_hz = 1000U;
bool arm_locked = true;

iFly::Shell shell;
iFly::ParameterManager params;

params.AddFloat({"pid.kp", "proportional gain", &kp, 0.0f, 100.0f, true, nullptr, nullptr});
params.AddU32({"sys.loop_hz", "loop frequency", &loop_hz, 50U, 4000U, true, nullptr, nullptr});
params.AddBool({"sys.arm_locked", "arming lock", &arm_locked, nullptr, nullptr});
params.RegisterToShell(&shell);

Usage Example

Pid：怎么用

用于单独验证控制器基础件，可直接完成单次更新和状态检查。

典型用法

  • 先定义 Pid::Config。
  • 用配置构造或调用 Configure()。
  • 准备 Pid::UpdateInput。
  • 调用 Update() 获得输出和分量。

最小示例

iFly::Pid::Config cfg {};
cfg.kp = 0.8f;
cfg.ki = 0.1f;
cfg.kd = 0.02f;
cfg.output_min = -500.0f;
cfg.output_max = 500.0f;

iFly::Pid pid(cfg);

iFly::Pid::UpdateInput input {};
input.setpoint = 100.0f;
input.measurement = 92.0f;
input.dt_s = 0.001f;

const iFly::Pid::UpdateResult out = pid.Update(input);

Usage Example

tick：怎么用

用于统一时间戳、阻塞延时和非阻塞定时器操作。

典型用法

  • NowMs() / NowUs() / NowNs() 读取当前时间。
  • DelayMs() / DelayUs() 做阻塞延时。
  • NonBlockingDelayMs 做轮询式非阻塞延时。

最小示例

const uint32_t start_ms = iFly::tick::NowMs();
iFly::tick::DelayMs(10U);

iFly::tick::NonBlockingDelayMs delay;
delay.Start(50U);

while (!delay.ConsumeIfExpired()) {
  // do something else
}

Usage Example

ObserverChannel：怎么用

用于构建轻量、无锁、单发布者多消费者的状态快照通道。

典型用法

  • 定义消息结构体。
  • 定义一个 ObserverChannel<Message>。
  • 发布侧调用 Publish() 或 Emplace()。
  • 消费者调用 SubscribeLatest() 或 SubscribeFromNext()。

最小示例

struct AttitudeSample {
  float roll;
  float pitch;
  float yaw;
};

iFly::ObserverChannel<AttitudeSample, 8U, 2U> attitude_channel;
auto consumer = attitude_channel.SubscribeLatest();

attitude_channel.Publish({1.0f, 2.0f, 3.0f});

AttitudeSample latest {};
if (consumer.TryReadLatest(latest) == iFly::ConsumeStatus::kOk) {
  // use latest
}

Usage Example

TaskManager：怎么用

用于在业务层以“任务”而不是“底层软定时器句柄”的方式组织定时逻辑。

典型用法

  • 通过 CreatePeriodicTask() 创建周期任务。
  • 通过 CreateOneShotTask() 创建单次任务。
  • 主循环持续调用 Dispatch()。
  • 任务内部可以调用 DelayCurrentTask() 重装下一次执行时间。

最小示例

void HeartbeatTask(void *context) {
  (void)context;
  // heartbeat logic
}

auto &task_mgr = iFly::task::TaskManager::Instance();
task_mgr.CreatePeriodicTask(&HeartbeatTask, nullptr, 10U);

for (;;) {
  task_mgr.Dispatch();
}

Usage Example

SbusProtocol：怎么用

用于从串口原始字节流中解析 SBUS 帧。

典型用法

  • 持续把串口收到的字节块喂给 Parse()。
  • 从输出数组中拿到成功解码的帧。
  • 如果需要反向打包，则调用 Encode()。

最小示例

iFly::SbusProtocol sbus;
uint8_t rx_bytes[64] {};
iFly::SbusFrame frames[2] {};

const uint32_t decoded = sbus.Parse(rx_bytes, sizeof(rx_bytes), frames, 2U);
if (decoded > 0U) {
  const uint16_t ch0 = frames[0].channels[0];
}

Usage Example

CrsfProtocol：怎么用

用于处理 CRSF 串流、CRC 校验和 RC Channels Packed 帧构造。

典型用法

  • 把原始字节流喂给 Parse()。
  • 如果帧类型是 kRcChannelsPackedType，再进一步解码 RC 通道。
  • 如果需要发包，可用 Encode() 或 EncodeRcChannelsPacked()。

最小示例

iFly::CrsfProtocol crsf;
iFly::CrsfFrame frames[2] {};
uint8_t rx_bytes[64] {};

const uint32_t decoded = crsf.Parse(rx_bytes, sizeof(rx_bytes), frames, 2U);
if (decoded > 0U && frames[0].type == iFly::CrsfProtocol::kRcChannelsPackedType) {
  iFly::CrsfRcChannelsPacked rc {};
  iFly::CrsfProtocol::DecodeRcChannelsPacked(frames[0], &rc);
}

Current Boundary

当前范围内不展开的内容

不假设完整飞控业务层已经存在

当前没有把姿态、遥控、控制分配和执行器输出拼成完整业务闭环，所以这页只讲模块和基础设施怎么用。

不把“已实现”写成“已接入主循环”

Observer、Task、SBUS、CRSF 这些模块已经可以独立使用，但当前是否进入主业务，要以架构页和实现页的状态说明为准。

不把 CLI 当成唯一目标

CLI 目前只是最好验证的入口，不代表整个工程的未来只能围绕 CLI 展开。

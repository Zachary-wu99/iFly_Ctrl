文档页的第一职责不是装饰，而是帮助后来的人快速判断：工程怎么启动、当前做到哪一步、模块怎么接、哪些内容已接入、哪些只是准备好但还没接到当前实际运行入口。 这页专门说明以后应该怎么改文档。

Principles

写文档前先守住这几条

先看代码，再下结论

文档不能根据目录名、类名或者未来规划猜状态。必须先确认模块是否真的被 main.c / app_main.cpp 接入当前实际运行路径。

状态必须分清楚

推荐统一使用三类表达：已接入、已实现但未接入、计划中。避免把“有代码”直接写成“正在工作”。

多写“为什么”，少写“文件存在”

例如不应只写“有 SerialIoBase 这个类”，而应解释为什么它要把 USB/UART/CAN 统一到同一套上层接口。

路径和名字要忠于仓库现状

例如目录名 paramete 虽然不理想，但文档里也必须保留真实路径，不能擅自改成“更正确”的写法。

Workflow

以后修改文档，按这套流程走

步骤 1：先确认改动源头

  • 如果是业务逻辑变了，先找入口函数和调用链。
  • 如果是模块能力变了，先看它是否真的被当前实际运行入口接入。
  • 如果只是命令、参数、说明文字变了，先核对实现文件里的注册表。

步骤 2：判断应该改哪一页

  • 影响使用方式，改“快速上手”。
  • 影响分层、启动流程、数据流，改“架构”。
  • 影响模块原理、代码入口、技术点，改“底层实现”。
  • 影响协作规范、链接维护、部署方式，改“文档协作”。

步骤 3：同步更新跳转

  • 如果新增模块或新增章节，必须补左侧目录锚点。
  • 如果某页新增重要入口，首页模块卡片和快速上手模块目录也要补跳转。
  • 新增正文时需同步补入口。

步骤 4：最后再做文案和样式优化

先确保事实对，再考虑页面呈现。内容错了，页面再整洁也没有意义。

Page Responsibility

具体内容应该落到哪一页

首页

  • 负责总览、状态摘要和四个主入口导流。
  • 不负责写满全部细节。
  • 如果首页开始堆很多实现细节，说明内容应该拆到别页。

快速上手

  • 负责构建命令、登录方式、常用命令和模块使用场景。
  • 负责给每个上手模块补“跳到底层实现”的入口。
  • 用于补充“怎么最快验证这条链路”这类内容。

架构说明

  • 负责启动流程、分层、目录结构、数据流、硬件资源和当前接入状态。
  • 用于补充“系统现在长什么样”这类内容。

底层实现

  • 负责模块职责、原理、技术点、代码阅读入口和当前状态。
  • 新增模块说明时优先补这里。
  • 如果模块多了，优先补目录和锚点，而不是让正文失去入口。

Sync Rules

跳转关系和 README 入口要一起维护

文档结构维护的重点之一，是避免出现“有内容但没有入口”或者“有入口但点过去找不到对应文档”的情况。

页面内锚点怎么维护

  • 新增章节时，同时补 id 和左侧目录链接。
  • 改章节标题时应保持 id 稳定，否则其他页面的跳转会失效。
  • 如果必须改 id，要全站搜一遍对应锚点并同步更新。

跨页面入口怎么维护

  • 首页负责总入口。
  • 快速上手页负责模块使用入口。
  • 底层实现页负责模块目录总索引。
  • 如果新增模块，至少要考虑这三处是否需要补入口。

README 应该同步什么

README 里至少应该给出文档首页入口，以及快速上手、架构、底层实现这三个最常用页面的链接。

## 文档入口
- 文档首页：<Pages 首页 URL>
- 快速上手：<Pages URL>/quickstart.html
- 架构说明：<Pages URL>/architecture.html
- 底层实现：<Pages URL>/implementation.html

站点目录里已经额外放了一份 README_文档入口模板.md，方便直接复制到仓库 README。

同步时的注意点

README 链接要指向已经发布的 Pages 地址，而不是本地磁盘路径。只有本地站点内部页面之间才用相对链接。

维护原则

新增内容时先问自己两个问题：用户从哪里能找到它？找到之后能不能继续跳到相关页面？如果这两个问题答不上来，就说明入口还没补齐。

Checklist

发起提交前的自检清单

事实一致性

  • 文档描述与当前代码一致。
  • 没有把“已实现未接入”写成“已运行”。
  • 类名、函数名、路径名都核对过。

入口完整性

  • 新增章节有锚点和侧边目录入口。
  • 新增模块时首页或快速上手页入口也同步补了。
  • 所有跨页面跳转都能点到对应位置。

工程价值

  • 解释了为什么这样设计。
  • 说明了当前边界和限制。
  • 能帮助后来的人判断下一步该从哪里接着做。

Pages Deployment

这份文档站怎么部署

站点性质

这是纯静态站点，只依赖 HTML / CSS / JS，不需要额外构建工具。

部署方式

  • 把站点文件放到仓库根目录，直接用仓库根目录发布。
  • 或者整体放到 docs/ 目录，再在仓库设置里启用 GitHub Pages。

需要一起发布的文件

  • index.html
  • quickstart.html
  • architecture.html
  • implementation.html
  • contributing.html
  • assets/ 目录

发布后别忘了

确认 README 里的文档入口已经指向最终 Pages URL，而不是旧链接或本地路径。

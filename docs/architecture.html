Current Position

当前工程定位

理解这一点以后，后面的架构才不会读偏。

现在是什么

现在是一个以 STM32F405 为底座、围绕通信、CLI、参数、控制基础件和协议模块展开的模块化工程。

现在不是什么

现在还不是一个已经把姿态估计、控制分配、执行器输出和调度完全拼起来的应用层飞控系统。

为什么要这样写架构

因为如果架构页过早围绕“主链路”描述，会把模块开发阶段误写成完整业务阶段，后面越写越不准确。

因此这页讲什么

这页只讲当前真实存在的工程层次、模块边界、目录结构、硬件资源和已落地能力。

这一层次的意义

底层硬件初始化继续交给 CubeMX，服务层处理收发和调度细节，device wrapper 统一上层接口，app 层专注模块能力，应用装配层只负责把需要的模块接起来。

App Layout

app 目录的模块结构

这里按职责而不是按文件名罗列。

交互与装配

  • app/cli/flight_ctrl_cli.*：终端场景装配。
  • app_main.cpp：把 transport 和 CLI 接到当前最小应用入口。

控制与参数

  • app/ctrl/pid.*：控制器基础件。
  • app/paramete/parameter_manager.*：参数注册与映射。

时间、观察者、任务

  • app/tick/tick.*：统一时间接口。
  • app/observer/observer_channel.hpp：观察者快照通道。
  • app/task_mage/task.*：基于 SoftTimer 的上层任务管理。

协议模块

  • app/proto/sbus/*：SBUS 帧解析与编码。
  • app/proto/crsf/*：CRSF 帧解析、CRC 和 RC Packed 处理。

Dev & Lib Layout

dev 和 lib 目录承担的角色

dev：对上统一接口

  • serial_io_base.hpp：统一字节流抽象。
  • uart_dev/：硬件 UART 包装器。
  • usb_dev/：USB CDC 包装器。
  • can_dev/：CAN 包装器。

lib：对下处理细节

  • usb_cdc/：USB CDC ACM 协议层。
  • uart/：UART DMA 服务。
  • can/：CAN 服务。
  • soft_timer/：非抢占式软定时器。
  • systick_timer/：HAL Tick + DWT 时间底座。

共享基础件

  • freelock_queue/：无锁队列。
  • double_buffer/：双缓冲。

这两层的关系

dev 负责给上层提供统一接口，lib 负责把具体硬件和运行时细节藏起来。这样上层切换 USB、UART、CAN 时，不需要改成完全不同的使用方式。

Current Status

当前状态应该怎么理解

已经落地的模块能力

  • CLI 与 Shell 交互
  • 参数系统
  • PID 控制器基础件
  • USB CDC 与 UART DMA 通信服务
  • tick 时间工具
  • Observer / Task / Protocol 模块代码

还没做成完整业务装配的内容

  • 应用层飞控任务调度
  • 姿态估计业务对象
  • 遥控输入到控制输出的完整闭环
  • 执行器和飞控业务状态对象

文档写法上的要求

  • 描述模块能力可以写“已实现”。
  • 描述应用层闭环时必须写“尚未拼装完成”。
  • 架构页不再拿不存在的主链路做主体。
